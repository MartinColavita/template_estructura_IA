# Índice de la sección tickets

Lo genera `python -I bin/puerta-skills.py --generar` con la primera oración de cada descripción: no se edita a mano.

- `analizar-tareas`: (Solo análisis, no escribe) Chequear la CONSISTENCIA del conjunto de Tareas que salió de partir una Historia (el paso "analyze"): que los Contratos OpenAPI no se pisen entre Tareas, que cada regla [RN-…] y cada ESCENARIO del Gherkin de la Historia tengan una Tarea que los cubra y un test que los...
- `auditar-historia`: (Solo lectura, adversarial) Auditar UNA Historia de usuario ya escrita —el segundo chequeo, hecho por un agente DISTINTO del que la redactó— antes de derivar Tareas de ella: que el Gherkin de los Criterios de aceptación sea VERIFICABLE (un Entonces observable y un comportamiento por Escenario, actor...
- `auditar-tarea`: (Solo lectura, adversarial) Auditar UNA Tarea técnica ya escrita —el segundo chequeo, hecho por un agente DISTINTO del que la redactó— con foco en la lista "Tests a escribir PRIMERO": que no falte ningún caso (cada validación, cada Caso de error, cada código del contrato OpenAPI, cada [RN-…] y cada...
- `cargar-a-azure`: (Avanzada / opcional) Con el MCP de Azure DevOps configurado y un PAT con scope de ESCRITURA, crear o actualizar el work item en el board a partir del ticket que produjo la skill redactar-tarea (create_work_item / update_work_item).
- `comentar-tarea`: Agregar un comentario a un work item de Azure DevOps (queda en el Historial / Discusión de la tarjeta) y, si hace falta, leer los comentarios existentes.
- `consultar-backlog`: (Solo lectura) Consultar y AUDITAR el backlog de Azure DevOps sin escribir nada: responder si una funcionalidad ya tiene historia y dónde está, auditar la COBERTURA (fichas del Cerebro Digital sin ticket, tickets sin documento fuente) y detectar DESFASE (drift) entre el documento vigente del Cerebro...
- `estimar-story-points`: Calcular los Puntos de historia (Story Points) de una historia / tarea / habilitador cuando el desarrollo lo hace la IA: el puntaje sale de la COMPLEJIDAD a nivel sistema + el CONSUMO DE TOKENS para resolver el desarrollo y para investigar historias/fichas relacionadas.
- `planificar-lote`: (Modo lote / planificación rápida) Derivar en una sola pasada, con agentes en paralelo, las Historias de una ficha del Cerebro, las Tareas de varias Historias, o las dos cosas, con SOLO DOS turnos humanos: el ARRANQUE (alcance + nivel + todas las dudas sin fuente, juntas y con recomendación) y el...
- `redactar-tarea`: Convertir un ticket POBRE (texto suelto, "ver adjunto", un link, o el ID de una tarjeta de Azure DevOps) en un work item PROFESIONAL, detallado y listo para pegar o crear en el board.
- `sincronizar-backlog`: Tomar una ficha del Cerebro Digital (cerebro-digital/) y DERIVAR de ella el árbol de tickets de Azure DevOps: Épica → Features → Historias (las Tareas quedan para Dev/planning).
- `tomar-tarea`: Antes de ponerse a trabajar una historia/tarea/bug de Azure DevOps, "tomarla": asignarla a la persona y pasarla a Active, avisando ANTES si ya la tomó otra persona (evita que dos trabajen la misma en paralelo y se desincronicen).
